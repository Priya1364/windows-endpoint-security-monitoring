Windows Endpoint Security Monitoring and Investigation Lab

1. Project Information

Project: Windows Endpoint Security Monitoring and Investigation Lab
Week: 1
Operating System: Windows 10 Pro, 64-bit
Primary Tool: Windows Event Viewer
Supporting Tools: PowerShell, Sysmon

2. Objective

The objective is to investigate Windows security logs, identify successful and failed logon events, understand event fields, and document findings for security monitoring.

3. Events Investigated

Event ID 4624 — Successful Logon

Description: An account successfully logged on.

Observation:
The inspected event showed the SYSTEM account and Logon ID 0x3E7.

Initial assessment:
This is consistent with a Windows SYSTEM logon session. The event alone does not indicate malicious activity.

Event ID 4625 — Failed Logon

Description: An account logon attempt failed.

Observation:
Three matching events appeared in the filtered Security log.

Details from the inspected event:

- Subject domain: WORKGROUP
- Subject logon ID: 0x3E7
- Target user name: -
- Target user SID: S-1-0-0
- Status: 0xC000006D
- Substatus: 0xC0000380
- Logon type: 2
- Logon process: User32
- Authentication package: Negotiate

Initial assessment:
The event records a failed interactive logon attempt. The available details are insufficient to determine the cause or attribute the attempt to a specific person or process.

Further investigation is required to interpret the status codes and correlate this event with surrounding security events.

4. Investigation Procedure

1. Opened Windows Event Viewer.
2. Navigated to Windows Logs > Security.
3. Inspected Event ID 4624.
4. Filtered the Security log for Event ID 4625.
5. Opened an event and inspected its Details tab.
6. Recorded the available event fields.
7. Avoided classifying the activity as malicious without sufficient evidence.

6. Conclusion

Windows Security logs provide useful evidence for investigating authentication activity.

Event ID 4624 records successful logons, while Event ID 4625 records failed logon attempts.

A SOC analyst should examine timestamps, account information, logon types, status codes, and related events before deciding whether an event represents suspicious activity.
